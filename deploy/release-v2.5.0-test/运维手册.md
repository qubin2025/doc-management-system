# 全过程工程咨询管理系统 — 运维手册（v2.5.0-test）

> 适用对象：系统运维/测试人员
> 环境：Windows 本机（手动部署形态）

---

## 一、服务一览

| 服务 | 端口 | 启动方式 | 停止方式 | 健康检查 |
|------|------|----------|----------|----------|
| 后端 API | 3000 | `cd backend && node server.js` | Ctrl+C / 杀进程 | `curl http://localhost:3000/api/health` |
| 前端 | 5300 | `npm run dev` | Ctrl+C | 浏览器访问 localhost:5300 |
| Neo4j | 7474/7687 | Docker Desktop 自动 | `docker stop doc-mgmt-neo4j` | `curl http://localhost:7474` |
| RAGFlow | 9380 | Docker Desktop 自动 | `docker compose -p docmgmt stop ragflow` | `curl http://localhost:9380` |
| LightRAG | 8000 | `python services/lightrag-server/main.py` | 杀进程 | `curl http://localhost:8000/api/lightrag/health` |
| PaddleOCR | 8001 | `python services/paddleocr-server/main.py` | 杀进程 | `curl http://localhost:8001/api/parse/health` |

> ⚠️ 所有本地服务验证**必须加 `--noproxy "*"`**（系统代理会误报离线）：
> `curl.exe -s --noproxy "*" http://localhost:3000/api/health`

## 二、启动顺序（机器重启后）

```
1. 启动 Docker Desktop（等待引擎就绪）→ Neo4j/RAGFlow 容器自动拉起
2. 启动后端  node server.js（在 backend 目录，Node v22.23.2）
3. 启动前端  npm run dev（项目根目录）
4. 启动 LightRAG（services/lightrag-server，注入 DEEPSEEK_API_KEY/DASHSCOPE_API_KEY）
5. 启动 PaddleOCR（services/paddleocr-server）
6. 验证：curl 各端口 + 浏览器访问 localhost:5300
```

## 五、数据备份与恢复

### 需要备份的数据

| 数据 | 位置 | 说明 |
|------|------|------|
| SQLite 主库 | `backend/data/planning.db` | 项目/用户/文档元数据/审计日志 |
| 上传文件 | `backend/files/` | 用户上传的工程文档 |
| Neo4j 图谱 | Docker volume `neo4j-data` | 知识图谱实体关系 |
| 向量数据 | SQLite 内嵌 / LightRAG volume | 文档向量 |

### 备份操作（手动）

```bash
# 1) 数据库备份（WAL 模式下用 SQLite backup API 更安全）
cd backend
node -e "const db=require('better-sqlite3')('./data/planning.db');db.backup('../backups/planning_YYYYMMDD.db').then(()=>console.log('ok'))"

# 2) 文件备份
Copy-Item -Recurse backend/files backend/backups/files_YYYYMMDD

# 3) Neo4j 备份（Docker）
docker exec doc-mgmt-neo4j bin/cypher-shell -u neo4j -p <password> "CALL dbms.backup('backup_dir')"  # 或直接备份 volume
```

### 恢复操作

```bash
# 数据库恢复：停止后端 → 覆盖 planning.db → 重启后端
# 文件恢复：停止后端 → 覆盖 files/ → 重启后端
```

> ⚠️ 测试期间至少保证**每周一次**完整备份；上线试运行期间建议每日。

## 六、常见故障排查

| 症状 | 可能原因 | 处理 |
|------|----------|------|
| 页面打不开（5300） | 前端未启动 | 启动 `npm run dev`；查 vite.out.log |
| API 报错 502/超时 | 后端未启动 | 启动 `node server.js`；curl health 验证 |
| 登录闪烁无法填写 | 浏览器插件/缓存 | 清理缓存；换无痕窗口 |
| 引擎全部显示离线 | Node fetch 代理误报 | 用 `curl --noproxy "*"` 验证；看 /api/stats |
| 上传失败 | base64 端点 50MB 限制 | 确认使用 multipart 端点（200MB） |
| 知识库存储已满 | localStorage 5MB 上限 | 使用"向量迁移"功能迁到后端 SQLite |
| 逻辑图无法保存 | 浏览器 localStorage 满 | 清 localStorage；用"重置连线"还原 |
| 机器重启后 RAGFlow 未起 | Docker 未启动 | 启动 Docker Desktop，等容器健康 |
| 后端 NODE_MODULE_VERSION 错误 | Node 版本不匹配 | 用 Node v22.23.2 并重装 backend 依赖 |

## 七、安全运维要点

1. **不要**将 `.env`、`backend/.env` 外发给任何人
2. 定期轮换 API Key（DeepSeek/DashScope/Zhipu/Qwen）
3. 修改默认密码后记录在安全保管处
4. 正式对外时配置防火墙：仅开放 80/443，3000/7474/8000/8001/9380 仅本机
5. 每日查看后端日志中的异常（`[BACKEND] WARN/ERROR`）
