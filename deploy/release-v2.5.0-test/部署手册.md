# 全过程工程咨询管理系统 — 测试环境部署手册

> 适用版本：v2.5.0-test
> 部署方式：A. 本机手动部署（本次实测方式）；B. Docker Compose 部署（生产推荐）
> 操作系统：Windows / Linux 均可

---

## 方式 A：本机手动部署（推荐用于测试试运行）

### A1. 环境准备

| 依赖 | 版本要求 | 检查命令 |
|------|----------|----------|
| Node.js | **v22.23.2**（必须） | `node -v` |
| npm | 10.x | `npm -v` |
| Python | 3.13.x | `python --version` |
| Docker Desktop | 4.66+（Neo4j/RAGFlow 需要） | `docker version` |

> ⚠️ **Node 版本注意事项**：后端使用 better-sqlite3 原生模块，Node 版本不匹配会报
> `NODE_MODULE_VERSION` 错误。当前项目实测运行于 Node v22.23.2。
> 如遇版本冲突，需重新执行 `cd backend && npm install` 重建原生模块。

### A2. 配置环境变量

```bash
# 后端（必填项）
cd backend
cp .env.example .env
# 编辑 .env 填入：
#   DEEPSEEK_API_KEY=sk-xxx        # 必填，AI 审查/方案生成
#   JWT_SECRET=<openssl rand -hex 32 生成>   # 必填，会话加密
#   DASHSCOPE_API_KEY=sk-xxx       # 推荐，语义搜索向量嵌入
#   ZHIPU_API_KEY=xxx              # 可选，GLM-4V 视觉
#   QWEN_API_KEY=sk-xxx            # 可选，千问视觉

# 前端（可选，若走 Nginx 反代则用 /api）
cd ..
cp .env.example .env
# VITE_API_URL=http://localhost:3000/api  # 开发直连后端
```

### A3. 安装依赖

```bash
# 后端
cd backend
npm install

# 前端
cd ..
npm install
```

### A4. 启动服务（按顺序）

```bash
# 1) 启动 Docker 引擎（Neo4j + RAGFlow 依赖）
#    打开 Docker Desktop，等待引擎就绪

# 2) 启动 Neo4j（Docker）
docker compose -p docmgmt up -d neo4j

# 3) 启动 RAGFlow（Docker，5 容器）
docker compose -p docmgmt up -d ragflow

# 4) 启动后端
cd backend
node server.js
# 或使用项目自带脚本（后台运行）：见 start-all.ps1 / start-all.bat

# 5) 启动前端（开发模式）
cd ..
npm run dev
```

### A5. 启动 Python 微服务（LightRAG + PaddleOCR）

```bash
# LightRAG（端口 8000）
cd services/lightrag-server
pip install fastapi uvicorn python-multipart requests numpy pydantic pdfplumber
set DEEPSEEK_API_KEY=sk-xxx
set DASHSCOPE_API_KEY=sk-xxx
python main.py

# PaddleOCR（端口 8001）
cd ../paddleocr-server
pip install fastapi uvicorn python-multipart pdfplumber python-docx openpyxl xlrd Pillow
python main.py
```

### A6. 验证部署

```bash
# 后端
curl http://localhost:3000/api/health
# 期望：{"status":"healthy","services":{"db":true,...}}

# 前端
打开浏览器访问 http://localhost:5300

# 全服务状态
curl http://localhost:3000/api/stats
# 期望：health 下 deepseek/qwen/zhipu/dashscope/neo4j/ragflow/paddleocr/lightrag 全部 true
```

## 方式 B：Docker Compose 部署（生产推荐）

### B1. 构建与启动

```bash
# 配置环境变量（宿主环境注入）
export DEEPSEEK_API_KEY=sk-xxx
export DASHSCOPE_API_KEY=sk-xxx
export JWT_SECRET=<64位随机字符串>   # 重要！覆盖 compose 默认值
export NEO4J_PASSWORD=<强密码>      # 重要！覆盖默认 changeme123

# 完整部署（Nginx + 后端 + Neo4j + LightRAG + PaddleOCR）
docker compose -p docmgmt up -d

# 最小部署（仅 Nginx + 后端，无需 Python/Docker 依赖）
docker compose -p docmgmt up -d backend nginx
```

### B2. 端口规划

| 服务 | 端口 | 对外 |
|------|------|------|
| Nginx（前端+API 反代） | 80 | ✅ 对外 |
| 后端 API | 3000 | 仅本机（127.0.0.1） |
| Neo4j | 7474/7687 | 仅本机 |
| LightRAG | 8000 | 仅本机 |
| PaddleOCR | 8001 | 仅本机 |

### B3. 部署后验证

```bash
curl http://localhost/api/health        # 经 Nginx 访问
curl http://localhost/api/stats         # 全引擎状态
```

## 常见部署问题

| 问题 | 原因 | 解决 |
|------|------|------|
| `NODE_MODULE_VERSION` 不匹配 | Node 版本与 better-sqlite3 编译版本不符 | 使用 Node v22.23.2，重装 backend 依赖 |
| 服务探针报 OFFLINE 但实际在线 | Node fetch 走系统代理 | 用 `curl --noproxy "*"` 验证；以 /api/health 为准 |
| RAGFlow 的 minio 拉取失败（quay.io 401） | quay.io 镜像仓库认证 | `docker tag minio/minio:latest quay.io/minio/minio:latest` 后重试 |
| 上传大文件失败 | 旧 base64 端点限制 50MB | 使用 multipart 端点（上限 200MB），见已知问题 #3 |
| 后端 .env 未生效 | 路径不对 | 确认在 `backend/` 下创建 .env（不是项目根） |
