# 部署操作手册

> 版本：v2.5.0-enterprise
> 日期：2026-08-13
> 适用环境：Windows / Linux 生产部署
> 系统名称：中航建科 · 工程咨询管理平台

---

## 一、系统概述

全过程工程咨询管理系统，四层架构：

| 层级 | 组件 | 技术 |
|------|------|------|
| L4 应用层 | 项目管理/目标管理/进度/成本/质量/风险/资料/AI对话 | React 18 + TypeScript + Tailwind CSS |
| L3 AI 层 | Agent 智能体/Skill 技能/MCP 协议/RAG 检索/AI 审查 | Multi-Agent 编排器 + 7 模型代理 |
| L2 知识层 | 知识图谱/向量存储/LightRAG/RAGFlow/智能分块 | Neo4j + 向量引擎 + RAGFlow |
| L1 数据层 | SQLite + localStorage + IndexedDB + Neo4j | better-sqlite3 + 浏览器存储 |

## 三、环境配置

### 3.1 后端配置 — `backend/.env`

复制 `backend/.env.example` 为 `backend/.env`，填入实际值：

```bash
# 必填
PORT=3000
DB_PATH=./data/planning.db
FILES_PATH=./files
JWT_SECRET=<生成32位以上随机字符串>

# AI 模型密钥（至少配置一个）
DEEPSEEK_API_KEY=sk-your-deepseek-api-key
ZHIPU_API_KEY=your-zhipu-api-key
QWEN_API_KEY=sk-your-qwen-api-key

# Neo4j 知识图谱（可选，不配置则使用离线模式）
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=changeme123

# 生产环境
NODE_ENV=production
CORS_ORIGIN=https://your-domain.com
```

> **JWT_SECRET 生成方法**：`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

### 3.2 前端配置 — `.env`

复制 `.env.example` 为 `.env`：

```bash
# 后端 API 地址（生产环境通过 Nginx 代理时使用 /api）
VITE_API_URL=http://localhost:3000/api

# 生产环境关闭离线演示入口
VITE_DISABLE_DEMO=true
```

### 3.3 Docker Compose 配置 — 根目录环境变量

在项目根目录创建 `.env` 文件（Docker Compose 自动读取）：

```bash
JWT_SECRET=<与后端相同的密钥>
NEO4J_PASSWORD=changeme123
DEEPSEEK_API_KEY=sk-your-deepseek-api-key
DASHSCOPE_API_KEY=sk-your-dashscope-api-key
```

## 四、启动命令

### 4.1 方式一：开发模式（本地调试）

```bash
# 1. 安装依赖
npm install
cd backend && npm install && cd ..

# 2. 启动后端（终端1，端口 3000）
node backend/server.js

# 3. 启动前端（终端2，端口 5300）
npx vite --host

# 4. （可选）启动 Docker 服务
docker compose -p docmgmt up -d neo4j ragflow
```

访问：`http://localhost:5300`

### 4.2 方式二：生产模式（PM2 + Nginx）

```bash
# 1. 构建前端静态文件
npm run build    # 产物输出到 dist/

# 2. 安装 PM2
npm install -g pm2

# 3. 启动后端（PM2 守护进程）
pm2 start deploy/ecosystem.config.cjs
pm2 save && pm2 startup    # 开机自启

# 4. 配置 Nginx
sudo cp deploy/nginx.conf /etc/nginx/sites-available/doc-mgmt
sudo ln -s /etc/nginx/sites-available/doc-mgmt /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

访问：`http://your-server-ip`（Nginx 80 端口）

### 4.3 方式三：Docker 全容器化部署

```bash
# 最小部署（仅后端 + Nginx，无需 Python 依赖）
docker compose -p docmgmt up -d backend nginx

# 完整部署（含知识图谱 + OCR + 本地AI）
docker compose -p docmgmt --profile full up -d

# 查看容器状态
docker compose -p docmgmt ps

# 查看日志
docker compose -p docmgmt logs -f backend
```

访问：`http://your-server-ip`（Nginx 80 端口）

### 4.4 Windows 快速启动

```bash
# 使用预置脚本
deploy\start.bat
```

## 六、数据库说明

### 6.1 SQLite（主数据库）

- 路径：`backend/data/planning.db`
- 表数量：32 张
- 核心表：`projects` / `documents` / `users` / `sessions` / `objectives` / `baselines` / `project_config` / `guide_forms` / `guide_progress` / `audit_log`

### 6.2 数据持久化链路

```
浏览器 localStorage (即时写入)
       ↓ syncService (每60秒)
后端 API /api/sync (POST)
       ↓
SQLite project_config 表 (upsert)
       ↓
GET /api/sync/:project (读回)
```

### 6.3 持久化覆盖范围（12 类配置数据）

| 数据类型 | 存储方式 | sync.js 落库 |
|---------|---------|-------------|
| objectives | API 直调 + sync 双写 | ✅ |
| tailoring / stakeholders / risks / resources / raci | sync → project_config | ✅ |
| guideProgress | API + sync 双写 | ✅ |
| knowledgeArtifacts | sync → project_config | ✅ |
| planFiles (CPM/甘特图) | sync → project_config | ✅ |
| 项目详情 (details JSON) | PUT /api/projects/:name | ✅ |
| 指南表单/样本/成果/AI提示词 | guide_forms 表 | ✅ |

## 七、部署后验证

### 7.1 健康检查

```bash
# 后端健康检查（返回服务状态）
curl http://localhost:3000/api/health

# 预期响应包含:
# "ai": true      (DeepSeek 在线)
# "kg": true      (Neo4j 在线)
# "ragflow": true (RAGFlow 在线)
```

### 7.2 持久化验证（API 往返测试）

```bash
# 1. 登录获取 token
TOKEN=$(curl -s -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | jq -r .token)

# 2. 验证 sync API（应返回 12 个配置键，含 planFiles）
curl -s http://localhost:3000/api/sync/all \
  -H "Authorization: Bearer $TOKEN" | jq 'keys'
# 预期: ["artifacts","baselines","docs","guideProgress","knowledgeArtifacts",
#        "objectives","planFiles","raci","resources","risks","stakeholders","tailoring"]

# 3. 验证项目列表
curl -s http://localhost:3000/api/projects \
  -H "Authorization: Bearer $TOKEN" | jq 'length'
# 预期: 项目数量 > 0
```

### 7.3 前端验证

1. 访问 `http://localhost:5300`（开发）或 `http://your-server-ip`（生产）
2. 使用 admin / admin123 登录
3. 验证项目列表加载、文档上传、指南进度保存
4. 刷新页面确认数据未丢失（持久化生效）

## 八、回滚方案

### 8.1 Git 回滚（代码层）

```bash
# 查看提交历史
git log --oneline -10

# 方式A：软回退（保留工作区改动，仅移动 HEAD）
git reset --soft <commit-hash>

# 方式B：创建回退提交（推荐，保留历史可追溯）
git revert <commit-hash>

# 方式C：回退到部署前检查点
git reset --soft aa51948   # 部署检查清单提交点
```

### 8.2 关键提交检查点

| Commit | 描述 | 回退到此的安全状态 |
|--------|------|------------------|
| `aa51948` | 部署检查清单最终版 | ✅ 全部修复完成，可部署 |
| `f17471e` | 延后项7 数据模块走API | ✅ 含缓存层 |
| `db55f4d` | 延后项6b plan-files持久化 | ✅ 含计划文件持久化 |
| `1667f23` | 部署检查清单初版 | ⚠️ 延后项未完成 |
| `f75a181` | 阻塞1修复 + mock清除 | ⚠️ 仅阻塞1修复 |

### 8.3 数据库回滚（数据层）

```bash
# 1. 部署前创建数据库快照（强烈建议）
cp backend/data/planning.db backend/data/planning.db.bak.$(date +%Y%m%d)

# 2. 回滚数据库
cp backend/data/planning.db.bak.20260813 backend/data/planning.db

# 3. 重启后端加载回滚后的数据库
pm2 restart doc-mgmt-backend
# 或
docker compose -p docmgmt restart backend
```

### 8.4 Docker 容器回滚

```bash
# 回退到上一个镜像版本
docker compose -p docmgmt down
git checkout <previous-release-tag> -- docker-compose.yml
docker compose -p docmgmt up -d

# 如需完全清理（慎用，会删除数据卷）
# docker compose -p docmgmt down -v
```

### 8.5 回滚决策树

```
问题类型？
├─ 代码Bug → git revert <commit> → 重新构建部署
├─ 数据异常 → 恢复 DB 快照 → 重启后端
├─ 容器故障 → docker compose restart → 检查日志
└─ 配置错误 → 修改 .env → 重启服务
```

## 十、故障排查

### 10.1 前端无法访问后端

```bash
# 检查后端是否运行
curl http://localhost:3000/api/health

# 检查 .env 中 VITE_API_URL 是否正确
# 开发: VITE_API_URL=http://localhost:3000/api
# 生产(Nginx): VITE_API_URL=/api

# 检查 CORS 配置
# backend/.env 中 CORS_ORIGIN 需匹配前端域名
```

### 10.2 登录返回 "登录已过期"

```bash
# JWT_SECRET 变更后所有 token 失效（正常行为）
# 用户重新登录即可

# 如频繁过期，检查 JWT 过期时间配置
# backend/routes/auth.js 中 jwt.sign 的 expiresIn 参数
```

### 10.3 Neo4j 连接失败

```bash
# 检查容器状态
docker ps | grep neo4j

# 检查 Neo4j 密码
# docker-compose.yml 中 NEO4J_AUTH=neo4j/${NEO4J_PASSWORD}
# backend/.env 中 NEO4J_PASSWORD 需一致

# 不配置 Neo4j 时系统自动降级为离线模式（不影响核心功能）
```

### 10.4 数据持久化失效

```bash
# 检查 syncService 是否运行（前端控制台 F12）
# 应看到 "[sync]" 日志，每 60 秒一次

# 检查后端 sync 端点
curl -X POST http://localhost:3000/api/sync \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"projectName":"test","data":{"tailoring":[]}}'

# 检查 SQLite 表完整性
sqlite3 backend/data/planning.db "PRAGMA integrity_check;"
```

### 10.5 Docker 容器启动失败

```bash
# 查看容器日志
docker compose -p docmgmt logs backend

# 常见原因:
# 1. 端口冲突 → 修改 docker-compose.yml 端口映射
# 2. .env 缺失 → 创建 backend/.env
# 3. 卷权限 → chmod -R 755 backend/data backend/files
```
