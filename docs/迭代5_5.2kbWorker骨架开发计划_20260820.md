## 一、核心状态流转图

### 1.1 任务状态机（kb_sync_queue.status 字段）

```
                    ┌───────────────────────────────────────┐
                    │                                       │
                    ▼                                       │
              ┌──────────┐                                  │
              │ pending  │ ← 新任务入队/超时回收/重试       │
              └────┬─────┘                                  │
                   │ Worker 领取任务                        │
                   │ (UPDATE status='processing'           │
                   │  SET locked_by, locked_at)             │
                   ▼                                        │
              ┌──────────┐                                  │
              │processing│                                  │
              └────┬─────┘                                  │
                   │                                        │
        ┌──────────┴──────────┐                            │
        │                     │                            │
        ▼ 成功                ▼ 失败                        │
   ┌─────────┐         ┌─────────────┐                     │
   │  done   │         │ retry_count │                    │
   │(终态)   │         │   < max?    │                    │
   └─────────┘         └──────┬──────┘                    │
                              │                           │
                   ┌──────────┴──────────┐                │
                   │ 是                   │ 否            │
                   ▼                      ▼               │
              ┌──────────┐         ┌──────────┐            │
              │ pending  │         │  failed  │            │
              │(重试)    │         │ (终态)   │            │
              └──────────┘         └──────────┘            │
                                                            
   超时回收（5 分钟未完成）:  processing → pending
   手动停止 Worker:           processing → pending（当前任务退回）
```

### 1.2 Worker 自身状态机

```
   ┌─────────┐  start()   ┌─────────┐  pause()   ┌─────────┐
   │ stopped │ ─────────▶│ running │ ─────────▶ │ paused  │
   └─────────┘           └────┬────┘            └────┬────┘
                               ▲ stop()              │ resume()
                               │                     │
                               └─────────────────────┘
                               │
              stop()           │ SIGTERM
        ┌──────────────────────┴──────────┐
        │ 优雅退出:                        │
        │  1. 停止轮询新任务                │
        │  2. 完成当前 processing 任务     │
        │  3. 退出主循环                   │
        └─────────────────────────────────┘
```

### 1.3 状态字段说明

| 字段 | 取值 | 含义 |
|------|------|------|
| `status` | `pending` | 待处理 |
| `status` | `processing` | 处理中（已被 Worker 锁定） |
| `status` | `done` | 处理完成（终态） |
| `status` | `failed` | 处理失败且重试上限（终态） |
| `locked_by` | worker id / NULL | 锁定任务的 Worker 标识 |
| `locked_at` | ISO 时间 / NULL | 锁定时间（用于超时回收） |
| `retry_count` | 0..max_retries | 已重试次数 |
| `processed_at` | ISO 时间 / NULL | 最近处理时间 |

## 二、关键日志埋点位置

### 2.1 日志级别与格式

```
[INFO ] 2026-08-20 14:30:15 [kbWorker] msg
[WARN ] 2026-08-20 14:30:15 [kbWorker] msg  
[ERROR] 2026-08-20 14:30:15 [kbWorker] msg
```

### 2.2 埋点位置清单（共 14 处）

| # | 位置 | 级别 | 日志内容 | 触发时机 |
|---|------|------|---------|---------|
| 1 | Worker 启动 | INFO | `Worker started, id=${workerId}, pollInterval=${interval}ms` | `start()` 调用 |
| 2 | Worker 停止 | INFO | `Worker stopping, currentTask will be released` | `stop()` / SIGTERM |
| 3 | Worker 已停止 | INFO | `Worker stopped, released ${n} stale tasks` | 主循环退出 |
| 4 | 轮询开始 | DEBUG | `Polling pending tasks, limit=${limit}` | 每轮循环 |
| 5 | 无任务 | DEBUG | `No pending tasks, sleeping ${interval}ms` | 队列为空 |
| 6 | 领取任务 | INFO | `Task locked: id=${taskId} source=${source} project=${project}` | UPDATE 成功 |
| 7 | 领取失败（被抢） | DEBUG | `Task ${taskId} already locked by other worker` | 0 行影响 |
| 8 | 处理开始 | INFO | `Processing task ${taskId}: ${source}/${recordId}` | processTask 入口 |
| 9 | 处理成功 | INFO | `Task ${taskId} done in ${duration}ms` | markDone 前 |
| 10 | 处理失败（可重试） | WARN | `Task ${taskId} failed (retry ${retry}/${max}): ${error}` | markRetry |
| 11 | 处理失败（终态） | ERROR | `Task ${taskId} permanently failed: ${error}` | markFailed |
| 12 | 超时回收 | WARN | `Recovered ${n} stale tasks (locked > 5min)` | recoveryStaleTasks |
| 13 | 异常捕获 | ERROR | `Unexpected error in poll cycle: ${error.stack}` | try/catch |
| 14 | 周期统计 | INFO | `Stats: processed=${n}, failed=${n}, avgMs=${avg}` | 每 60s |

```javascript
// 埋点 10: 处理失败（可重试）

// 埋点 12: 超时回收
```

## 三、代码骨架方案（5.2 不做实际解析嵌入）

### 3.1 模块结构

```
backend/services/kbWorker.js
├── WorkerState (枚举: STOPPED/RUNNING/PAUSED)
├── KbWorker 类
│   ├── constructor(config)
│   ├── start()              → 启动主循环
│   ├── stop()               → 优雅退出
│   ├── pause() / resume()   → 暂停/恢复
│   ├── getStats()           → 返回统计
│   ├── _pollOnce()          → 单轮轮询
│   ├── _lockTask(task)      → 领取任务（事务）
│   ├── _processTask(task)   → 处理任务（5.3 填充）
│   ├── _markDone(task)      → 标记成功
│   ├── _markRetry(task, err)→ 标记重试
│   ├── _markFailed(task, err)→ 标记终态失败
│   ├── _recoverStale()      → 超时回收
│   └── _logStats()          → 周期统计
└── 单例导出: kbWorker
```

### 3.2 核心方法骨架（伪代码）

```javascript
class KbWorker {
  constructor(config = {}) {
    this.workerId = `kbw-${Date.now()}-${Math.random().toString(36).slice(2, 6)}`;
    this.state = 'stopped';
    this.pollInterval = config.pollInterval || 2000;  // 2s
    this.batchSize = config.batchSize || 5;
    this.staleTimeoutMs = 5 * 60 * 1000;  // 5 分钟
    this.maxConcurrent = config.maxConcurrent || 3;
    this.stats = { processed: 0, failed: 0, retried: 0, recovered: 0, lastError: null };
    this._timer = null;
    this._statsTimer = null;
  }

  start() {
    if (this.state === 'running') return;
    this.state = 'running';
    logger.info(`Worker started, id=${this.workerId}, pollInterval=${this.pollInterval}ms`);
    this._schedulePoll();
    this._statsTimer = setInterval(() => this._logStats(), 60000);
    // SIGTERM 优雅退出
    process.once('SIGTERM', () => this.stop());
    process.once('SIGINT', () => this.stop());
  }

  async _pollOnce() {
    if (this.state !== 'running') return;
    try {
      // 1. 超时回收
      const recovered = this._recoverStale();
      // 2. 拉取 pending 任务
      const tasks = db.prepare(
        `SELECT * FROM kb_sync_queue 
         WHERE status='pending' 
         ORDER BY priority DESC, created_at ASC LIMIT ?`
      ).all(this.batchSize);
      if (tasks.length === 0) { logger.debug('No pending tasks'); return; }
      // 3. 逐个处理
      for (const task of tasks) {
        if (this.state !== 'running') break;
        await this._processOne(task);
      }
    } catch (err) {
      logger.error(`Poll cycle error: ${err.message}`);
      this.stats.lastError = err.message;
    }
  }

  async _processOne(task) {
    // 1. 领取任务（原子操作）
    const locked = db.prepare(
      `UPDATE kb_sync_queue 
       SET status='processing', locked_by=?, locked_at=datetime('now')
       WHERE id=? AND status='pending'`
    ).run(this.workerId, task.id);
    if (locked.changes === 0) return;  // 被其他 Worker 抢走
    logger.info(`Task locked: id=${task.id} source=${task.source}`);

    // 2. 处理任务（5.3 填充实际逻辑，5.2 用 mock）
    try {
      await this._processTask(task);
      this._markDone(task);
    } catch (err) {
      this._markRetry(task, err);
    }
  }

  async _processTask(task) {
    // ★ 5.2 阶段：mock 处理，仅打日志
    // ★ 5.3 阶段：调用 docParser + chunker + embeddingService + vectorStore
    logger.info(`[MOCK] Processing task ${task.id}: ${task.source}/${task.record_id}`);
    await new Promise(r => setTimeout(r, 100));  // 模拟处理耗时
  }

  _markDone(task) {
    db.prepare(
      `UPDATE kb_sync_queue SET status='done', processed_at=datetime('now'), error_msg=NULL WHERE id=?`
    ).run(task.id);
    this.stats.processed++;
    logger.info(`Task ${task.id} done`);
  }

  _markRetry(task, err) {
    const newRetry = task.retry_count + 1;
    if (newRetry >= task.max_retries) {
      this._markFailed(task, err);
    } else {
      db.prepare(
        `UPDATE kb_sync_queue SET status='pending', retry_count=?, error_msg=?, locked_by=NULL, locked_at=NULL WHERE id=?`
      ).run(newRetry, err.message.slice(0, 500), task.id);
      this.stats.retried++;
      logger.warn(`Task ${task.id} retry ${newRetry}/${task.max_retries}: ${err.message}`);
    }
  }

  _markFailed(task, err) {
    db.prepare(
      `UPDATE kb_sync_queue SET status='failed', retry_count=?, error_msg=?, processed_at=datetime('now') WHERE id=?`
    ).run(task.max_retries, err.message.slice(0, 500), task.id);
    this.stats.failed++;
    logger.error(`Task ${task.id} permanently failed: ${err.message}`);
  }

  _recoverStale() {
    const result = db.prepare(
      `UPDATE kb_sync_queue 
       SET status='pending', locked_by=NULL, locked_at=NULL 
       WHERE status='processing' AND locked_at < datetime('now', '-5 minutes')`
    ).run();
    if (result.changes > 0) {
      logger.warn(`Recovered ${result.changes} stale tasks`);
      this.stats.recovered += result.changes;
    }
    return result.changes;
  }

  stop() {
    if (this.state === 'stopped') return;
    this.state = 'stopping';
    logger.info('Worker stopping, releasing current tasks');
    // 退回当前 processing 任务
    db.prepare(
      `UPDATE kb_sync_queue SET status='pending', locked_by=NULL, locked_at=NULL WHERE locked_by=?`
    ).run(this.workerId);
    if (this._timer) clearTimeout(this._timer);
    if (this._statsTimer) clearInterval(this._statsTimer);
    this.state = 'stopped';
    logger.info('Worker stopped');
  }

  getStats() {
    return {
      workerId: this.workerId,
      state: this.state,
      stats: this.stats,
      queue: db.prepare(
        `SELECT status, COUNT(*) as cnt FROM kb_sync_queue GROUP BY status`
      ).all().reduce((acc, r) => ({ ...acc, [r.status]: r.cnt }), {})
    };
  }
}
```

```javascript
async _processTask(task) {

  // 5.3: 实际逻辑

  const record = this._fetchRecord(task);
  // 2. 文本分块

  // 3. 批量嵌入

  // 4. 入库 vector_embeddings
  this._storeVectors(task, chunks, embeddings);
}
```

## 六、风险与回退

| 风险 | 应对 |
|------|------|
| Worker 异常崩溃 | 超时回收机制保证任务不丢失（5 分钟后自动 pending） |
| SQLite 锁竞争 | better-sqlite3 同步 API，单进程无锁竞争 |
| 内存溢出（大文档） | 5.3 填充时加分块大小限制 + 处理完释放 |
| 重复处理 | 任务锁（locked_by）保证不重复 |
