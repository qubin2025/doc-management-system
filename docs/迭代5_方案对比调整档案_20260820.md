## 二、SQLite Schema 设计（豆包建议 + 项目适配）

```sql
CREATE TABLE IF NOT EXISTS vector_embeddings (
  id          TEXT PRIMARY KEY,        -- chunk唯一id
  project     TEXT NOT NULL,           -- 项目隔离
  doc_id      TEXT NOT NULL,           -- 源文档id
  doc_name    TEXT,                    -- 源文档名
  chunk_index INTEGER,                  -- 分块序号
  text        TEXT NOT NULL,            -- 原文
  embedding   BLOB NOT NULL,            -- 向量二进制(Float32Array)
  dimension   INTEGER NOT NULL,         -- 向量维度(便于后续换模型)
  sensitivity INTEGER DEFAULT 0,        -- 敏感度分级(0公开/1内部/2机密)
  metadata    TEXT,                      -- JSON: 页码/章节/文件类型等
  created_at  TEXT DEFAULT (datetime('now')),
  updated_at  TEXT DEFAULT (datetime('now'))
);
CREATE INDEX idx_vec_project ON vector_embeddings(project);
CREATE INDEX idx_vec_doc ON vector_embeddings(project, doc_id);
CREATE INDEX idx_vec_sens ON vector_embeddings(project, sensitivity);
```

**注意**：SQLite 不支持向量相似度查询，需应用层计算（按 project 过滤后加载到内存，计算余弦相似度取 topK）。数据量 ≤10 万条可接受，超过后迁移到 pgvector/Qdrant/RAGFlow。

## 五、核心差异总结

1. **新增前置任务**：先确认环境（接口格式/表结构）再写代码，避免返工
2. **拆分实施**：kbWorker.js 分骨架→填充两步，不一次性生成完整代码
3. **向量存储明确**：SQLite 表 + 应用层相似度计算（而非文件）
4. **任务保护扩展**：从单点重试扩展为 9 项保护机制
5. **新增迁移脚本**：前端向量数据迁移到后端，避免数据丢失
6. **双跑期保留**：前端 kbQueueProcessor 不立即删除，降级备份 1-2 周
7. **检索接口同步改**：明确 vectorStore.searchAll 移到后端，前端通过 API 调用
