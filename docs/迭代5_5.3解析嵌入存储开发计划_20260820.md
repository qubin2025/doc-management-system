## 一、DashScope 批量嵌入接口参数要求

### 1.1 接口定义

```
POST https://dashscope.aliyuncs.com/api/v1/services/embeddings/text-embedding/text-embedding
Content-Type: application/json
Authorization: Bearer {DASHSCOPE_API_KEY}
```

### 1.2 请求体（Request Body）

```json
{
  "model": "text-embedding-v1",
  "input": {
    "texts": ["文本1", "文本2", ..., "文本N"]
  },
  "parameters": {
    "text_type": "document"   // "document" 文档检索索引 | "query" 查询向量
  }
}
```

### 1.3 参数约束

| 参数 | 类型 | 必需 | 约束 | 说明 |
|------|------|------|------|------|
| `model` | string | ✅ | `text-embedding-v1` / `v2` / `v3` | 本项目用 v1（1536 维） |
| `input.texts` | string[] | ✅ | **1-25 条/批** | 每批最多 25 条文本 |
| `input.texts[i]` | string | ✅ | **≤ 2048 tokens** | 超长需分块 |
| `parameters.text_type` | string | ❌ | `document` / `query` | 索引时用 document，查询时用 query |
| **QPS 限制** | — | — | 免费 2 QPS / 付费 10 QPS | 控制并发避免 429 |

### 1.4 响应体（Response Body）

```json
{
  "output": {
    "embeddings": [
      { "embedding": [0.0123, -0.0456, ..., 0.0789] },  // 1536 维 Float
      { "embedding": [0.0234, -0.0567, ..., 0.0890] }
    ]
  },
  "request_id": "xxx-xxx-xxx",
  "usage": { "total_tokens": 1234 }
}
```

### 1.5 错误响应

| HTTP | code | 说明 |
|------|------|------|
| 400 | InvalidParameter | 文本为空/超长 |
| 401 | InvalidApiKey | API Key 无效 |
| 429 | Throttling | QPS 超限（需重试） |
| 500 | InternalError | 服务异常 |

### 1.6 实测数据（5.0 调研）

| 测试 | 结果 |
|------|------|
| 单条嵌入 | 361ms, 维度 1536 |
| 批量 10 条 | 260ms, 平均 26ms/条 |
| 批量效率 | 比单条调用快 14 倍 |

### 1.7 embeddingService.js 设计要点

1. **批量分片**：每 25 条为一批，自动切分
2. **并发控制**：并发=3（避免 429）
3. **超时**：单批 30s
4. **重试**：429 错误指数退避（1s, 2s, 4s）
5. **降级**：单条失败时降级为逐条嵌入

## 二、docParser 需要支持的文档格式清单

### 2.1 支持的文档格式

| 扩展名 | MIME | Node 库 | 状态 | 备注 |
|--------|------|---------|------|------|
| `.pdf` | application/pdf | `pdf-parse` | 待选型 | 备选 `pdfjs-dist` 的 node 入口 |
| `.docx` | application/vnd.openxmlformats | `mammoth` | ✅ Node 可用 | 提取纯文本 |
| `.doc` | application/msword | ❌ 不直接支持 | 降级 | 转图片→OCR 或建议用户转 docx |
| `.xlsx` | application/vnd.openxmlformats | `xlsx` (SheetJS) | ✅ Node 可用 | 按表单分块 |
| `.xls` | application/vnd.ms-excel | `xlsx` | ✅ 兼容 | 同上 |
| `.csv` | text/csv | 原生 | ✅ | 按行解析 |
| `.txt` | text/plain | 原生 fs | ✅ | 直接读取 |
| `.md` | text/markdown | 原生 fs | ✅ | 直接读取 |
| `.json` | application/json | 原生 JSON | ✅ | 解析后扁平化 |
| `.html` | text/html | `cheerio` 或正则 | ✅ | 去标签 |
| 图片 OCR | image/* | `paddleocr-server :8001` | ✅ 已是后端 | HTTP 调用 |

### 2.2 docParser.js 接口设计

```javascript
/**
 * 解析文档为纯文本
 * @param {Buffer} buffer - 文件 Buffer
 * @param {string} fileName - 文件名（含扩展名）
 * @returns {Promise<{text: string, pages?: string[], meta: object}>}
 */
async function parseDocument(buffer, fileName) {
  const ext = path.extname(fileName).toLowerCase();
  switch (ext) {
    case '.pdf':  return parsePdf(buffer);
    case '.docx': return parseDocx(buffer);
    case '.xlsx': case '.xls': return parseXlsx(buffer);
    case '.csv':  return parseCsv(buffer);
    case '.txt':  case '.md': return parseText(buffer);
    case '.json': return parseJson(buffer);
    case '.html': case '.htm': return parseHtml(buffer);
    default:
      // 兜底：按文本读取
      return parseText(buffer);
  }
}
```

### 2.3 PDF 解析备选方案

| 库 | 优点 | 缺点 | 选择 |
|----|------|------|------|
| `pdf-parse` | 简单、纯 Node | 中文支持一般 | ✅ 首选 |
| `pdfjs-dist` | 完整、中文好 | 需配置 canvas | 备选 |
| `paddleocr` | OCR 任何 PDF | 慢、需调服务 | 扫描件用 |

策略：先用 pdf-parse，若中文乱码再降级 paddleocr。

### 2.4 业务记录文本化策略（非文档）

kbWorker 主要处理**业务记录**（daily_reports/mobile_issues/project_experiences），不是文件。文本化规则：

| source | 文本化规则 | 字段 |
|--------|----------|------|
| `daily` | 4 段拆块：进度/质量风险/现场问题/原文备注 | tasks, quality_risks, issues, notes + original_text |
| `issue` | 单条文本：标题+描述+严重度 | title + description + severity |
| `experience` | 单条文本：标题+描述+模式+指标 | title + description + patterns + metrics |

## 三、chunker.js 设计

### 3.1 复用前端 chunker 策略

前端 `src/data/chunker.ts` 是纯 TS 无浏览器依赖，转 Node.js 模块：
- 删除 ES Module 类型注解
- 删除任何 import.meta.url
- 保留三种策略：固定窗口/语义分块/表格分块

### 3.2 分块策略

| 策略 | 参数 | 适用场景 |
|------|------|---------|
| `fixed` | size=500, overlap=50 | 通用文本 |
| `semantic` | minSize=200 | 按段落/标题 |
| `table` | 保留完整表格 | 表格内容 |

### 3.3 文本预处理

- 去除多余空白（连续空格→1个）
- 去除控制字符
- 超长文本（>50000 字符）告警并截断
- 空文本跳过（不嵌入）

## 四、kbWorker._processTask 实际逻辑

### 4.1 完整流程

```
_processTask(task)
  │
  ├─ 1. 拉取业务记录 _fetchRecord(task)
  │     ├─ source='daily'     → SELECT * FROM daily_reports WHERE id=?
  │     ├─ source='issue'     → SELECT * FROM mobile_issues WHERE id=?
  │     └─ source='experience'→ SELECT * FROM project_experiences WHERE id=?
  │
  ├─ 2. 文本化 _buildText(task, record)
  │     ├─ daily     → 4 段：[进度段, 质量风险段, 现场问题段, 备注+原文段]
  │     ├─ issue     → [title + severity + description]
  │     └─ experience→ [title + description + patterns + metrics]
  │
  ├─ 3. 分块 chunker.chunk(text, { strategy:'fixed', size:500 })
  │     └─ 跳过空文本块
  │
  ├─ 4. 批量嵌入 embeddingService.embedBatch(chunks, 'document')
  │     ├─ 每 25 条/批
  │     ├─ 并发=3
  │     └─ 超时 30s
  │
  ├─ 5. 入库 vector_embeddings _storeVectors(task, chunks, embeddings)
  │     ├─ 去重：先删 project + doc_id 旧向量
  │     ├─ 批量 INSERT（事务）
  │     └─ metadata: { source, recordId, segmentIndex, page, ... }
  │
  └─ 6. 内存释放 chunks/embeddings/record = null
```

### 4.2 _fetchRecord 实现

```javascript
_fetchRecord(task) {
  const db = getDb();
  if (task.source === 'daily') {
    return db.prepare('SELECT * FROM daily_reports WHERE id=?').get(task.record_id);
  }
  if (task.source === 'issue') {
    return db.prepare('SELECT * FROM mobile_issues WHERE id=?').get(task.record_id);
  }
  if (task.source === 'experience') {
    return db.prepare('SELECT * FROM project_experiences WHERE id=?').get(task.record_id);
  }
  throw new Error(`Unknown source: ${task.source}`);
}
```

### 4.3 _buildText 实现（daily 4 段拆块）

```javascript
_buildTextSegments(task, record) {
  if (task.source === 'daily') {
    return [
      { segment: 1, label: '进度', text: record.tasks || '' },
      { segment: 2, label: '质量风险', text: record.quality_risks || '' },
      { segment: 3, label: '现场问题', text: record.issues || '' },
      { segment: 4, label: '备注+原文', text: [record.notes, record.original_text].filter(Boolean).join('\n') },
    ].filter(s => s.text.trim().length > 0);
  }
  if (task.source === 'issue') {
    const text = [record.title, `[严重度:${record.severity}]`, record.description].filter(Boolean).join('\n');
    return [{ segment: 1, label: '问题', text }];
  }
  if (task.source === 'experience') {
    const text = [record.title, record.description, record.patterns, record.metrics].filter(Boolean).join('\n');
    return [{ segment: 1, label: '经验', text }];
  }
  return [];
}
```

### 4.4 _storeVectors 实现

```javascript
_storeVectors(task, segments, embeddings) {
  const db = getDb();
  const projectId = this._lookupProjectId(task.project_name);
  const sensitivity = task.sensitivity || 0;
  // 去重：删旧向量
  const prefix = `${task.source}-${task.record_id}`;
  db.prepare('DELETE FROM vector_embeddings WHERE project=? AND doc_id=?').run(task.project_name, prefix);
  // 批量 INSERT
  const insert = db.prepare(
    `INSERT INTO vector_embeddings (id, project, doc_id, doc_name, chunk_index, text, embedding, dimension, sensitivity, metadata)
     VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)`
  );
  const tx = db.transaction((rows) => {
    for (const r of rows) insert.run(...r);
  });
  const rows = [];
  for (let i = 0; i < segments.length; i++) {
    const seg = segments[i];
    const emb = embeddings[i];
    if (!emb || !seg.text.trim()) continue;
    const id = `${prefix}-seg${seg.segment}`;
    const buf = Buffer.from(new Float32Array(emb).buffer);
    rows.push([
      id, task.project_name, prefix, task.doc_name || `${task.source}-${task.record_id}`,
      i, seg.text, buf, emb.length, sensitivity,
      JSON.stringify({ source: task.source, recordId: task.record_id, segment: seg.segment, label: seg.label })
    ]);
  }
  tx(rows);
  return rows.length;
}
```
