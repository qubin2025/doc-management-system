## 一、开发方案概述

方案核心定位为**「统一资料入口归集 + 提交自动向量化入库 + 全域知识库赋能业务」**的单向闭环架构，定义了 5 个开发优先级：

| 优先级 | 内容 | 方案要求 |
|--------|------|---------|
| 第一 | 统一数据归集入口改造 | 资料模块 + 全业务模块提交归集接口统一 |
| 第二 | 数据解析 + 标准化清洗中台 | PDF/Word/图片解析、工程数据标准化 |
| 第三 | 向量化生成 + 项目专属知识库 | 语义分块、Embedding、项目级隔离 |
| 第四 | 全模块 AI 自动填表、分析报告、智能校验 | AI 能力 100% 依赖知识库 |
| 第五 | 版本管控、权限隔离、数据溯源 | 增量更新、版本追溯、删除联动 |

## 五、风险与不足

### 5.1 已知不足

1. **文档入库不完整**：document upsert 任务由 processor 跳过（标记 synced=0, skipped=1），实际文档解析入库仍依赖 ProjectEntryPage 上传时的 parsedText。未实现"processor 自动拉取文档内容并解析入库"的完整链路。
2. **智能分析报告未实现**：方案要求"造价/进度/质量/结算分析报告自动生成"，当前仅 Dashboard 有图表，无 AI 生成报告。
3. **版本追溯未实现**：方案要求"历史向量版本留存"，当前 vectorStore 仅支持 removeByPrefix 去重后重新入库，不保留历史版本。
4. **权限隔离未实现**：方案要求"按项目角色配置检索权限"，当前 vectorStore 按项目分键但不做角色级权限控制。

### 5.2 架构风险

1. **向量库容量**：localStorage 上限 5-10MB，IndexedDB 200MB 软上限。大项目（>4MB）已降级到 IndexedDB，但仍需监控容量预警。
2. **processor 并发**：前端 processor 单线程轮询，处理速度受浏览器限制。大批量任务时可能积压。
3. **嵌入服务依赖**：embedText 依赖后端 AI 接口（/api/ai/embed），AI 服务不可用时入库失败。
