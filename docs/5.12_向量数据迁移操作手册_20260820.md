# 5.12 向量数据迁移操作手册

> **版本**：v1.0 · 2026-08-20
> **适用场景**：将浏览器 localStorage 中的旧向量数据迁移到后端 SQLite `vector_embeddings` 表
> **目标读者**：系统管理员、项目经理（具备 admin 或 project_manager 角色）
> **预计耗时**：5-15 分钟（取决于数据量）

---

## 一、迁移背景与目标

### 1.1 为什么需要迁移

v5.6 之前，系统所有向量数据都存储在浏览器 localStorage 中（键名 `vector-store-${project}`）。这种存储方式存在以下问题：

- **容量限制**：localStorage 单域上限 5-10MB，超过会抛 QuotaExceededError
- **数据不共享**：A 浏览器的数据 B 看不到，无法跨设备协作
- **清理即丢失**：用户清理浏览器缓存后所有向量数据丢失
- **检索性能差**：前端遍历计算余弦相似度，数据量 >1000 条时明显卡顿

v5.6 引入后端 `kbWorker.js` + SQLite `vector_embeddings` 表后，所有新数据直接入后端。但 localStorage 中的历史数据需要主动迁移。

### 1.2 迁移目标

| 项 | 迁移前 | 迁移后 |
|----|--------|--------|
| 存储位置 | 浏览器 localStorage | 后端 SQLite vector_embeddings 表 |
| 检索方式 | 前端遍历余弦相似度 | 后端 SQL + FTS5 + 向量检索 |
| 跨设备共享 | ❌ 不可共享 | ✅ 全平台共享 |
| 容量上限 | ~5MB | SQLite 单表 ~1TB |
| 持久性 | 清缓存即丢 | 数据库文件永久保存 |

### 1.3 迁移后数据保留情况

迁移过程**只复制不删除** localStorage 原始数据，确保数据安全：

- ✅ localStorage 中的 `vector-store-*` 数据**完整保留**
- ✅ 后端 `vector_embeddings` 表新增对应记录（按 id 去重，重复 id 执行 INSERT OR REPLACE）
- ✅ 后端 `vector_embeddings_fts`（FTS5 全文索引）同步更新
- ✅ 文档原文 `text`、向量 `embedding`、`metadata` 完整保留
- ⚠️ 迁移完成后，建议手动清理 localStorage（详见第五章）

### 2.4 检查 localStorage 数据量

在浏览器中执行（F12 → Console）：

```javascript
// 统计 localStorage 中所有 vector-store-* 数据
let totalDocs = 0;
let totalBytes = 0;
for (let i = 0; i < localStorage.length; i++) {
  const k = localStorage.key(i);
  if (k && k.startsWith('vector-store-')) {
    const data = JSON.parse(localStorage.getItem(k) || '{}');
    if (Array.isArray(data?.vectors)) {
      totalDocs += data.vectors.length;
      totalBytes += (localStorage.getItem(k) || '').length;
    }
  }
}
console.log(`总计 ${totalDocs} 条向量数据，约 ${(totalBytes / 1024 / 1024).toFixed(2)} MB`);
```

- > 2000 条 / > 20MB：建议分项目分批迁移（详见第六章）

## 四、迁移过程数据安全保护

### 4.1 双写不删策略

迁移过程采用"只复制不删除"策略，确保数据安全：

- localStorage 原始数据完整保留
- 后端按 `id` 去重（INSERT OR REPLACE）
- 即使迁移中途失败，localStorage 中的数据不会丢失

### 4.2 事务原子性

每批 100 条在后端使用 SQLite 事务包裹，保证原子性：

```javascript
// backend/routes/kbSync.js 中的事务逻辑
const tx = db.transaction((rows) => {
  for (const d of rows) {
    insertVec.run(...);  // vector_embeddings 表
    deleteFts.run(d.id);  // 删除旧 FTS5 索引
    insertFts.run(...);  // 插入新 FTS5 索引
  }
});
tx(docs);
```

- 事务成功：100 条全部入库
- 事务失败：100 条全部回滚，不影响其他批次

### 4.3 字段映射规则

| localStorage 字段 | 后端字段 | 转换规则 |
|-------------------|---------|---------|
| `id` | `id` | 直接复制（主键去重） |
| `text` | `text` | 截断到 8000 字符 |
| `embedding` (number[]) | `embedding` (BLOB) | `Buffer.from(new Float32Array(arr).buffer)` |
| `embedding.length` | `dimension` | 自动提取 |
| `metadata.projectName` | `project` | 缺省值 `'default'` |
| `metadata.fileName` | `doc_name` | 缺省值 = id |
| `metadata.chunkIndex` | `chunk_index` | 缺省值 0 |
| `metadata.sensitivity` | `sensitivity` | 缺省值 0（公开） |
| `metadata` (整体) | `metadata` | JSON 序列化存储 |

### 4.4 字段验证规则

后端对每条记录做字段验证，无效记录会被跳过（计入 `skipped`）：

- `id` 必须是非空字符串
- `text` 必须是非空字符串
- `embedding` 必须是非空 number 数组

被跳过的记录会在响应中返回错误原因：

```json
{
  "success": true,
  "inserted": 98,
  "skipped": 2,
  "errors": [
    { "id": "abc", "reason": "invalid fields" },
    { "id": "def", "reason": "embedding array empty" }
  ],
  "totalErrors": 2
}
```

## 五、迁移后清理（可选但推荐）

### 5.1 验证后端数据完整

迁移完成后，**先验证后端数据完整**，再清理 localStorage：

```bash

# 按项目统计分布
node -e "const db = require('better-sqlite3')('data/planning.db'); console.log(db.prepare('SELECT project, COUNT(*) as c FROM vector_embeddings GROUP BY project').all());"
```

### 5.2 备份 localStorage（强烈推荐）

清理前先备份 localStorage 数据到本地文件：

```javascript
// 在浏览器 Console 中执行
const backup = {};
for (let i = 0; i < localStorage.length; i++) {
  const k = localStorage.key(i);
  if (k && k.startsWith('vector-store-')) {
    backup[k] = localStorage.getItem(k);
  }
}
const blob = new Blob([JSON.stringify(backup)], { type: 'application/json' });
const url = URL.createObjectURL(blob);
const a = document.createElement('a');
a.href = url;
a.download = `localStorage-backup-${new Date().toISOString().slice(0, 10)}.json`;
a.click();
URL.revokeObjectURL(url);
console.log(`备份完成，共 ${Object.keys(backup).length} 个项目数据`);
```

### 5.3 清理 localStorage

确认备份完成且后端数据正常后，清理 localStorage：

```javascript
// 在浏览器 Console 中执行
let cleared = 0;
for (let i = localStorage.length - 1; i >= 0; i--) {
  const k = localStorage.key(i);
  if (k && k.startsWith('vector-store-')) {
    localStorage.removeItem(k);
    cleared++;
  }
}
console.log(`已清理 ${cleared} 个 vector-store-* 键`);
```

### 5.4 刷新页面验证

清理后刷新知识库页面：
- 所有数据应来自后端
- 检索功能正常
- 5.11 监控面板显示后端统计数据

## 六、高级场景

### 6.1 大数据量分项目迁移

如果 localStorage 数据量 > 20MB（>2000 条），建议按项目分批迁移，避免单次请求过大。

**临时清理其他项目数据**：

```javascript
// 仅保留当前要迁移的项目数据，其他项目先备份
const keepProject = 'default';  // 改成要迁移的项目名
for (let i = localStorage.length - 1; i >= 0; i--) {
  const k = localStorage.key(i);
  if (k && k.startsWith('vector-store-') && k !== `vector-store-${keepProject}`) {
    // 备份到 window 变量，不删除
    if (!window._backup) window._backup = {};
    window._backup[k] = localStorage.getItem(k);
    localStorage.removeItem(k);
  }
}
console.log(`仅保留 ${keepProject} 项目数据`);
```

迁移完成后恢复其他项目数据：

```javascript
// 恢复备份
if (window._backup) {
  for (const [k, v] of Object.entries(window._backup)) {
    localStorage.setItem(k, v);
  }
  console.log(`已恢复 ${Object.keys(window._backup).length} 个项目数据`);
}
```

### 6.2 通过 API 手动迁移（脚本方式）

如果 UI 迁移失败，可通过 curl 手动调用 API：

```bash
# 1. 登录获取 token

  -H "Content-Type: application/json" ^
  -d "{\"username\":\"admin\",\"password\":\"admin123\"}" | ConvertFrom-Json).token

# 2. 从浏览器导出 localStorage 数据为 JSON 文件
#    （参考 5.2 节的备份脚本）

# 3. 用 Node.js 分批迁移

for (const [k, v] of Object.entries(docs)) {
  const data = JSON.parse(v);
  if (Array.isArray(data?.vectors)) allDocs.push(...data.vectors);
}
console.log('总计', allDocs.length, '条');
// 分批 100 条调用 API
// ...
"
```

### 6.3 迁移失败回滚

如果迁移过程中出现严重错误，需要回滚：

1. **后端清理**（删除本次迁移的所有记录）：
   ```bash
   # 找到迁移开始时间，删除之后插入的记录
   node -e "const db = require('better-sqlite3')('data/planning.db'); const r = db.prepare(\"DELETE FROM vector_embeddings WHERE created_at > datetime('now','-1 hour')\").run(); console.log('清理', r.changes, '条');"
   ```

2. **localStorage 恢复**：localStorage 原始数据未删除，无需恢复。

3. **检查后端 FTS5 索引**：
   ```bash
   node -e "const db = require('better-sqlite3')('data/planning.db'); const r = db.prepare(\"DELETE FROM vector_embeddings_fts WHERE external_id NOT IN (SELECT id FROM vector_embeddings)\").run(); console.log('清理孤立 FTS5 索引', r.changes, '条');"
   ```

## 七、故障排查

### 7.1 常见错误及解决

| 错误现象 | 可能原因 | 解决方案 |
|---------|---------|---------|
| 点击"迁移本机数据"无反应 | 后端服务未启动 | 检查后端端口 3000 |
| 迁移按钮灰色不可点 | 正在迁移中（migrating=true） | 等待当前迁移完成 |
| "单批最多 200 条"错误 | 前端分批失败 | 检查网络，重试 |
| "docs 不能为空"错误 | localStorage 无 vector-store-* 数据 | 确认数据存在 |
| inserted=0, skipped=N | 字段验证失败 | 查看后端日志中的 errors 字段 |
| 401 Unauthorized | token 过期 | 重新登录 |
| 403 Forbidden | 角色权限不足 | 使用 admin 或 project_manager 账号 |

### 7.2 后端日志查看

后端日志输出到 stdout，包含详细迁移信息：

[kb/migrate] user=admin batch=100 inserted=100 skipped=0

### 7.3 数据一致性检查

迁移后做数据一致性检查：

```bash
node -e "
const db = require('better-sqlite3')('data/planning.db');
const totalVec = db.prepare('SELECT COUNT(*) as c FROM vector_embeddings').get().c;
const totalFts = db.prepare('SELECT COUNT(*) as c FROM vector_embeddings_fts').get().c;
console.log('vector_embeddings:', totalVec);
console.log('vector_embeddings_fts:', totalFts);
if (totalVec !== totalFts) {
  console.warn('⚠️ 数量不一致，建议重建 FTS5 索引');
} else {
  console.log('✅ 数据一致');
}
"
```

如发现不一致，重建 FTS5 索引：

```bash
node -e "
const db = require('better-sqlite3')('data/planning.db');
db.exec('DELETE FROM vector_embeddings_fts;');
const rows = db.prepare('SELECT id, text FROM vector_embeddings').all();
const ins = db.prepare('INSERT INTO vector_embeddings_fts (text, external_id) VALUES (?, ?)');
const tx = db.transaction(() => rows.forEach(r => ins.run(r.text, r.id)));
tx();
console.log('FTS5 索引重建完成:', rows.length, '条');
"
```
