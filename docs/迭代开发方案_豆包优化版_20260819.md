# 迭代开发方案（豆包优化版）— 原方案 vs 优化建议 对比

**生成日期**：2026-08-19
**基于**：《全过程工程咨询管理系统-资料归集+向量化知识库+AI赋能实施方案》+ 已完成迭代1-3 经验 + AI 行业通用最佳实践

---

## 一、核心差异点对比

### 1.1 开发优先级对比

| 优先级 | 原方案 | 豆包优化建议 | 差异说明 |
|--------|--------|-------------|---------|
| **第一** | 统一数据归集入口 | 统一数据归集入口 | 一致，核心入口统一原则不变 |
| **第二** | 数据解析+标准化清洗 | **数据安全+权限隔离前置** | 🔴 **重大调整**：原方案将权限隔离放在第五优先级，优化建议将其提升至第二，理由是企业级系统安全必须前置，数据在入库前就应有权限标记 |
| **第三** | 向量化+项目专属知识库 | 数据解析+标准化清洗 | 原方案的清洗中台降至第三，先安全后清洗 |
| **第四** | AI 自动填表+分析报告+智能校验 | 向量化+知识库（含缓存优化） | 新增"Embedding 缓存"要求，避免重复嵌入计算 |
| **第五** | 版本管控+权限隔离 | **AI 能力+智能分析报告** | 原方案的版本管控降至第五，AI 业务价值提前交付 |
| **新增** | 无 | **RAG 检索优化（混合检索+重排序）** | 原方案仅提"高速向量检索"，优化建议增加关键词+向量混合检索和结果重排序 |
| **新增** | 无 | **架构解耦（队列处理后端化）** | 原方案队列处理在前端，优化建议移至后端避免浏览器限制 |

### 1.2 核心规则对比

| 规则 | 原方案 | 豆包优化建议 | 评估 |
|------|--------|-------------|------|
| 所有 AI 能力禁止直查数据库 | ✅ 已确立 | ✅ 保持 | 一致 |
| 提交即入库 | ✅ 已确立 | ✅ 保持 | 一致 |
| 项目维度数据隔离 | ✅ 已确立 | ✅ 保持 + 增加"字段级权限" | 优化：从项目级隔离扩展到字段级权限 |
| 无手动导入入库 | ✅ 已确立 | ⚠️ 微调：允许"管理员手动触发重嵌入" | 理由：嵌入结果错误时需要修正能力 |
| 数据安全前置 | ❌ 未明确 | ✅ 新增：入库前标记敏感字段 | 原方案只在第五优先级提权限，优化建议要求入库时就标记敏感等级 |

### 1.3 架构对比

| 维度 | 原方案 | 豆包优化建议 | 差异影响 |
|------|--------|-------------|---------|
| 队列处理位置 | 前端（kbQueueProcessor.ts） | 后端（Worker 服务） | 🔴 高：避免前端单线程限制+浏览器崩溃丢失任务 |
| 检索策略 | 纯向量检索 | 向量+关键词混合检索+重排序 | 🟡 中：提升检索准确率，特别是技术术语匹配 |
| Embedding 缓存 | ❌ 无 | ✅ 相同文本缓存嵌入结果 | 🟡 中：降低 API 调用量 30-50% |
| 版本追溯 | 第五优先级 | 与 AI 能力并行 | 🟡 中：审计需求提前满足 |
| 公共知识库 | 提及但未规划 | 新增独立迭代 | 🟡 中：通用规范/标准模板沉淀 |
| 错误监控 | ❌ 无 | ✅ 队列处理失败告警+重试超限通知 | 🟢 低：运维体验改善 |

## 四、关键风险与缓解措施

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 后端 Worker 嵌入服务不稳定 | 入库失败积压 | 重试+降级缓存+失败任务告警通知 |
| 混合检索技术选型 | 实现复杂度高 | 先用规则重排序（5.8 降级为简单规则），后续升级 Cross-Encoder |
| 权限改造影响现有功能 | 已有路由被锁定 | 权限中间件默认放行，仅对敏感接口生效 |
| 公共知识库数据来源 | 初始为空 | 预置 50+ 工程规范模板（造价/进度/质量标准） |
| 版本追溯存储膨胀 | 向量库容量增长 | 归档策略 + 版本数限制（≤5 版本） |
