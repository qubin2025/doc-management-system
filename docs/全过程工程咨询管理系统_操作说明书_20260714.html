一、系统概述

全过程工程咨询管理系统是一个以目标管理为驱动、以PMBOK第6/7版为内核、以AI智能体为引擎的全过程工程咨询管理平台。系统覆盖项目从前期工作、招标采购、工程施工到竣工验收的全生命周期。

能力层包含模块
项目管理目标管理 · 模块裁剪 · 全过程指南 · PMBOK框架 · 干系人 · 风险 · 资源 · 基线 · 仪表盘 · 进度 · 成本 · 质量 · 资料 · 供应商 · 归档
AI智能Agent智能体 · Skill技能面板(7个) · AI审查(施工/合同/招投标) · AI方案生成 · AI表单填写 · AI对话(7模型) · MCP协议
知识工程知识编排器 · 知识图谱(3D) · RAG检索 · 向量存储 · LightRAG · RAGFlow
系统管理用户管理 · 审计日志 · 数据备份 · 项目管理 · 模型配置 · 主题切换
首次使用建议按引导流程操作：创建项目 → 模块裁剪 → 目标管理 → 进入工作首页。

一.附、系统数据哲学与核心理念

本系统的设计哲学源于一个根本认知：建设工程项目是单一的、一次性的、不可复制的。 这个认知决定了我们对待数据的方式与传统的工程管理软件截然不同。

传统数据思维的局限

传统工程管理软件的做法是：先设计一套"干净的、标准的"指标体系，试图用一个统一的模板去衡量每一个项目。比如要求填写"进度偏差率"、"成本偏差率"、"质量合格率"等有限指标，然后与"类似项目"对比，给出"你的进度落后了3.2%"这样的结论。

这种做法的问题在于：有限的指标根本无法描述一个项目的全貌和独特性。 当一个项目的复杂性被压缩为几个百分比数字时，它已经被"杀死"了——它不再是那个有着独特的场地条件、独特的团队构成、独特的施工挑战的活生生的工程，而变成了一个可被平均的统计样本。最终，这些数据成为一堆鸡肋——既不能真正指导决策，也无法为下一个项目提供有意义的参考。

本系统的数据哲学

核心理念：全量数据收集 > 标准化指标提取

我们不预设"哪些数据是重要的"。我们收集项目生命周期中的全部数据——日报的每一个字段、每一张现场照片、每一次安全检查的记录、每一个协调问题的来龙去脉、每一台机械的进出场时间、每一批材料的规格和数量。让数据本身说话，而不是让人为预设的指标体系替数据说话。

这一理念源于《大数据时代》的核心洞见：在大数据时代，我们不再依赖抽样，而是拥抱全量数据；我们不再追求精确性，而是接受混杂性；我们不再执着于因果关系，而是关注相关关系。 AI大模型近乎无限的全方位向量化分析能力，使我们第一次有可能为每一个项目描绘一个数字化全貌——不是几个冰冷的指标，而是一个完整的、丰满的、一望便知的项目肖像。

六个数据原则

#原则说明系统体现
1 全量收存 不预设重要性筛选，收集项目全生命周期产生的全部数据 日报8板块全字段入库、施工照片原图保存、原始DOCX双份存档（数据库+专用硬盘）
2 拒绝裁剪 不为了"标准化"而丢弃任何数据。每个项目的独特细节都是其DNA的一部分 结构化数据库保留完整JSON字段，原始文档保留一字不改
3 AI驱动关联 利用AI大模型的向量化分析能力，从全量数据中自动发现关系、趋势、模式 DeepSeek日报解析、Recharts趋势图表、知识图谱25类节点全要素关联
4 项目即样本 每个完成的项目都是一个完整的、可供后续项目参考的真实样本 项目经验库自动提取模式、干系人/风险/进度数据全留存、跨项目对比分析
5 以PMBOK为纲 以《项目管理指南》的准则和行动要素为骨架，系统化地组织和归纳数据 5大过程组×10大知识领域为框架，Objective/Progress/Risk数据按PMBOK结构组织
6 可见即可信 不满足于"报表数字"，追求数据的完整性和可视化，让项目的全貌一望便知 3D知识图谱、Dashboard实时图表、日报全8板块展开视图、施工照片时间轴

系统的终极目标

为全过程工程咨询、项目管理、工程管理提供活生生的样本和可借鉴模型。

它们是完整的、丰满的，一望便知的——无论是美的还是丑陋的。

通过本系统，可见的是以此作为下一个项目的指路者，而非一堆冰冷的数字报表。

数据不为归档而生，数据为下一个项目而生。

二、快速入门

1
登录系统
打开浏览器访问系统地址。默认管理员账户：admin / admin123。系统支持4种角色：管理员、项目经理、建设单位、查看者。
2
创建项目
在项目入口页点击「创建新项目」，输入项目名称。系统自动进入引导流程。
3
模块裁剪
填写项目特征问卷（类型、规模、复杂度、管理范围等），系统根据PMBOK规则自动推荐必选/推荐/可选模块。
4
设定目标
创建WBS目标树（项目总目标→阶段目标→交付物→工作包），关联工作指南中的工作项。
5
开始工作
进入首页，使用各功能模块。根据裁剪结果，指南中会标记必选/推荐/可选工作项。

三、项目创建与引导

3.1 创建项目

登录后进入项目入口页，可以看到已有项目列表。点击右上角「创建新项目」按钮，输入项目名称即可。

创建后系统自动跳转到模块裁剪引擎。如果选择已有项目，系统会根据配置状态智能跳转：

项目状态跳转目标
无裁剪配置→ 模块裁剪引擎
有裁剪、无目标→ 目标管理
配置完备→ 工作首页

3.2 首页导航

首页按功能分为三个区域：

区域包含模块
功能模块AI智能体 · 技能面板 · PMBOK框架 · 模块裁剪 · 目标管理 · 资料管理 · 仪表盘 · 进度计划 · 供应商 · 造价 · 知识库 · 分析中心 · AI审查/生成等
管理模块干系人管理 · 风险管理 · 资源与沟通 · 基线管理
高级工具工作流引擎 · 审计日志（管理员）

四、模块裁剪引擎

4.1 填写项目特征问卷

裁剪引擎分为两步：填写问卷 → 查看结果。

问卷涵盖以下维度：

  • 项目类型：建筑工程 / 市政工程 / 工业工程 / 综合工程
  • 投资规模：小型(＜5000万) ~ 特大型(＞10亿)
  • 计划工期：月数
  • 项目复杂度：简单 / 常规 / 复杂 / 高复杂度
  • 管理范围：10个领域多选（前期、招标、施工、竣工、造价、进度、质量、安全、合同、资料）
  • 特殊需求：文保、环评、交通影响、地下施工、特殊结构、市政管线
  • 组织特征：参与方数量、设计管理、招标代理
可使用「快速模板」一键填充常见项目类型的预设值。

4.2 查看裁剪结果

点击「生成裁剪方案」后，系统根据20条PMBOK裁剪规则计算每个工作项的状态：

标记含义在指南中的表现
必选该项目必须执行左侧红色标记 + "必选"徽章
推荐建议执行蓝色星标
可选默认状态正常显示
排除该项目不需要灰显

每个工作项的状态可以手动调整（点击「必/荐/可/排」按钮）。保存配置后自动应用到工作指南。

五、目标管理（WBS树）

5.1 创建目标层级

目标管理采用WBS四层分解结构：

层级说明示例
root · 总目标项目最高目标"项目按时高质量交付"
phase · 阶段目标按阶段分解"前期工作按时完成"
deliverable · 交付物可交付成果"施工许可证取得"
work-item · 工作包最小工作单元"施工图审查通过"

5.2 关联工作项

每个目标可以关联工作指南中的工作项。目标进度会根据关联工作项的完成状态自动计算：

  • 叶子节点进度 = 已完成关联工作项数 / 总关联工作项数
  • 非叶子节点进度 = 子节点加权平均
  • 点击「刷新进度」手动触发重算

5.3 目标树操作

  • 新增目标 — 点击右上角「新增目标」
  • 添加子目标 — 悬停目标行，点击「+」
  • 编辑/删除 — 悬停显示编辑和删除按钮
  • 展开/折叠 — 点击目标前的箭头
  • 权重设置 — 编辑弹窗中拖拽滑块（0-100%）

六、全过程工作指南

工作指南按工程行业DB11规程分为4个章节，每个章节包含三个Tab：

6.1 工作模块 Tab

以子模块卡片形式展示工作项列表。每个工作项可以：

  • 勾选"计划" — 标记为正在执行（蓝色）
  • 勾选"完成" — 标记为已完成（绿色）
  • 全选/取消全选 — 子模块级别批量操作
  • 编辑工作项 — 点击编辑按钮，可上传流程图、添加附件、拆解子任务
  • AI拆解子任务 — 上传流程图或输入描述，AI自动拆解为子任务步骤
  • AI办理指南 — AI根据附件信息自动生成办理流程和注意事项

6.2 时序逻辑图 Tab

以流程图形式展示工作项之间的依赖关系。支持：

  • 缩放 — 25%~200%
  • 编辑模式 — 拖拽连线创建依赖关系
  • 只读模式 — 查看流程图

6.3 附表清单 Tab

展示本章节对应的工程附表模板。每个附表可以：

  • 编辑内容 — 打开编辑弹窗，支持Markdown格式
  • AI自动填写 — 根据项目上下文自动填充表单字段
  • 保存 — 保存到localStorage
裁剪配置会自动标记工作项的必选/推荐状态，子模块标题会显示统计（必X/推X/可X）。

视图内容

八、干系人/风险/资源管理

8.1 干系人管理

包括干系人登记册和权力/利益矩阵(2x2)：

  • 登记册记录干系人的姓名、角色、组织、权力、利益、参与策略
  • 2x2矩阵自动分类：高权力高利益(密切管理)、高权力低利益(令其满意)、低权力高利益(随时告知)、低权力低利益(监督)

8.2 风险管理

包括风险登记册和概率×影响矩阵(5x5)：

  • 每条风险记录名称、类别、概率(1-5)、影响(1-5)、评分(=概率×影响)、应对措施、负责人
  • 5x5热力图显示风险分布，红色(≥15高风险)、橙色(8-14中风险)、绿色(<8低风险)

8.3 资源与沟通

包含三个Tab：

  • 团队 — 成员登记（姓名、角色、部门、可用性）
  • RACI矩阵 — 任务×角色的责任分配（R执行/A负责/C咨询/I知会）
  • 沟通记录 — 会议纪要模板和信息分发记录

九、基线管理

基线管理用于记录项目关键指标的基准快照，支持后续对比和变更追踪：

  • 支持三大基线类型：范围基线、进度基线、成本基线
  • 每次创建新基线，旧基线自动标记为"非活跃"
  • 当前KPI值（CPI/SPI/完整度/质量分）与基线值对比显示
  • 支持多版本管理
基线创建后不可修改内容（只能创建新版本或删除）。请确认数据无误后再创建。

十、AI智能体与技能面板

10.1 AI智能体 (Agent Console)

输入自然语言目标，Agent自动规划多步执行计划：

1
输入目标
如"对项目进行健康检查"、"审查施工方案"、"生成周报"。
2
Agent规划
LLM分析目标 → 制定多步JSON计划 → 展示步骤列表。
3
执行与确认
逐步执行，变更类操作(如填表、索引)弹出确认对话框。每步显示状态(执行中/已完成/失败)。
4
查看结果
全部步骤完成后生成综合摘要。

Agent拥有11个内置工具：ai_chat、compute_kpi、scan_workitems、scan_forms、knowledge_search、knowledge_graph、rag_search、index_document、fill_form、health_check等。

十一、AI审查/生成/对话

11.1 AI审查

审查类型输入输出
施工组织设计审查上传施工方案文件逐章节审查结果(pass/warn/fail) + 综合报告
合同审查上传合同文件条款风险分级 + 修改建议

11.2 AI方案生成

支持7种方案模板：施工组织设计、深基坑方案、塔吊方案、脚手架方案、模板方案、临时用电方案、冬期施工方案。

11.3 AI对话

支持7种AI模型切换：DeepSeek-V3/V4 Pro/R1、通义千问、智谱GLM-4、Ollama Qwen/Llama。

功能特性：多会话管理、RAG开关（自动检索项目文档增强回答）、文件/图片上传、延伸建议、对话导出。

十二、仪表盘与分析中心

12.1 项目仪表盘

实时显示四大核心指标：

指标说明正常范围
CPI（成本绩效指数）已签合同额/批复概算0.95~1.05
SPI（进度绩效指数）已完成工作项/总工作项≥0.8
完整度实际上传文档数/基准80≥60%
质量分综合评分≥75

告警可点击：成本告警→跳转基线管理、进度告警→跳转进度计划、完整度告警→跳转资料管理。

12.2 智能分析中心

提供一次性的综合扫描：工作项扫描 + 表单扫描 + KPI计算 + AI综合建议。同时展示知识图谱概览。

十三、工作流引擎

工作流步骤

在首页「工作流引擎」卡片中展开查看步骤，点击「执行」即可运行。

十六、管理员功能

16.1 用户管理

管理员（admin角色）可以：创建用户、修改用户角色/权限、启用/禁用账户、删除用户。

十八、常见问题

Q: AI功能不可用怎么办？

A: 检查 .env 中是否配置了有效的 DEEPSEEK_API_KEY。系统会自动降级：先尝试后端代理 → 直连DeepSeek API → 离线关键词分析。

Q: 知识图谱显示为空？

A: 知识图谱需要项目中有数据（工作项、文档、表单等）才会显示。确认项目中有实际操作后再查看。

Q: 如何修改管理员密码？

A: 管理员登录后，在「系统管理」→「用户管理」中可修改用户密码。

Q: 数据存储在哪里？

A: 工作状态和配置存储在前端localStorage，项目和文档数据存储在后端SQLite数据库。数据库文件路径：backend/data/planning.db。

Q: 如何备份数据？

A: 首页「数据备份」按钮可下载ZIP备份。服务器端可配置cron定时备份（参考 scripts/backup.sh）。

Q: 支持哪些浏览器？

A: Chrome 90+、Edge 90+、Firefox 88+、Safari 15+。

二十三、知识图谱构建原则与关系体系

系统知识图谱以 3D 力导向图 展示项目全要素关系网络，支持 5 种主题光效（深空黑/暮光紫/星光蓝/破晓金/月光白），是理解系统数据全貌的核心工具。

23.1 五大构建原则

原则说明应用示例
① 数据驱动仅对有实际数据存储的模块构建节点，不虚构数据。图谱反映系统真实状态项目有干系人数据→生成干系人节点；无数据→不生成
② 项目锚定所有节点最终通过边（Edge）关联到项目根节点，确保图谱以项目为中心展开风险→项目、审查报告→项目、供应商→项目
③ 关系优先每个节点类型必须有至少一种有意义的边关系，孤立节点不生成belongs-to / references / assigned-to / produces / precedes / reviews
④ 全量覆盖所有产生持久化数据的模块均应在图谱中有对应节点类型31 个模块中有 localStorage 数据的 25 个已入图
⑤ 可查询图谱应能回答项目管理关键问题，支持搜索节点、追溯关系链「该项目有哪些风险」「谁负责哪些审查」

二十四、项目日报数据存储与管理方案

项目日报是工程管理的数据基石，承载人员、机械、材料、进度、安全等全维度信息。系统采用 SQLite 结构化数据库 + 专用硬盘原始文档归档 双存储架构。

24.1 方案选型与对比

方案全量留存可视化私有化部署成本匹配度
SQLite + 专用硬盘（已采用）⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐极低⭐⭐⭐⭐⭐
PostgreSQL + MinIO（企业级）⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐中⭐⭐⭐
MongoDB + GridFS（NoSQL）⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐中⭐⭐
云SaaS（简道云/明道云）⭐⭐⭐⭐⭐⭐⭐月费⭐

选型结论：SQLite 零部署成本、完全离线、即开即用，完美匹配项目私有化交付需求。云SaaS方案因数据存在第三方服务器，违反数据主权原则，直接排除。
